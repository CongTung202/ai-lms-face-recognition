Hình 3.1. Thiết kế tổng quát gói (UML Package Diagram)

Phân chia 3 tầng độc lập: Tầng Presentation (UI), Tầng Business (com.datn.lms), Tầng DataManagement.
💡 Hướng dẫn vẽ lại trên Visual Paradigm / Draw.io:
  • Chọn hình Package (hình thư mục có tai tab ở góc trên bên trái).
  • Vẽ 2 Package lớn đại diện cho 2 tầng: com.datn.lms (Business Tier) và DataManagement.
  • Bên trong mỗi tầng, đặt các Package con tương ứng. Tầng ngoài gồm Web UI và PayOS Gateway.
  • Kéo các mũi tên nét đứt có nhãn Dependency hướng từ tầng trên trỏ xuống tầng dưới.
@startuml
skinparam style strictuml
skinparam packageStyle rectangle
skinparam defaultTextAlignment center

package "Web UI" as UI
package "PayOS Gateway" as PayOS

package "com.datn.lms (Business Tier)" as Business {
    package "Auth & User" as Pkg_Auth
    package "CourseManagement" as Pkg_Course
    package "FaceAIService" as Pkg_FaceAI
    package "PaymentService" as Pkg_Payment
    
    Pkg_Course ..> Pkg_Auth
    Pkg_Course ..> Pkg_FaceAI
    Pkg_Payment ..> Pkg_Course
}

package "DataManagement Tier" as Data {
    package "MySQL Repositories" as Repo_MySQL
    package "MongoDB (Chunks/RAG)" as Repo_Mongo
}

UI ..> Pkg_Course
PayOS ..> Pkg_Payment
Pkg_Course ..> Repo_MySQL
Pkg_FaceAI ..> Repo_MySQL
Pkg_Payment ..> Repo_MySQL
Pkg_Course ..> Repo_Mongo
@enduml

Hình 3.2. Thiết kế chi tiết các gói (Detailed Package Dependencies)

Mô tả các quan hệ phụ thuộc chi tiết với stereotype <<access>> và <<import>>.
💡 Ý nghĩa các quan hệ Stereotype:

- <<access>>: Cho phép gói nguồn gọi và truy cập các API / Service công khai của gói đích.
- <<import>>: Gói nguồn nhập toàn bộ không gian tên (namespace / entities) của gói đích để sử dụng trực tiếp các đối tượng dữ liệu. 

@startuml
skinparam style strictuml
skinparam packageStyle rectangle
skinparam defaultTextAlignment center

package "UI Framework" as UI
package "Course & Learning" as Course
package "Face AI Verification" as FaceAI
package "Payment PayOS" as Payment

UI ..> Course : <>
UI ..> FaceAI : <>
Course ..> FaceAI : <>
Payment ..> Course : <>
@enduml

Hình 3.5. Sơ đồ lớp chủ đạo (UML Class Diagram)

Chuẩn UML: Tên lớp, Thuộc tính (- private), Phương thức (+ public), Kế thừa (tam giác rỗng) và Liên kết đa bội (1, 1..*, 0..*).
💡 Điểm nổi bật chuẩn UML giống hệt ảnh mẫu của trường:

- Hộp lớp chia 3 phần rõ ràng: Tên lớp (in nghiêng nếu trừu tượng), Thuộc tính (dấu - thể hiện private), Phương thức (dấu + thể hiện public).
- Các quan hệ kết hợp có chỉ số đa bội 1, 1..*, 0..*.
- Mũi tên tam giác rỗng hướng lên lớp cha Order (Transaction) thể hiện tính chất kế thừa đa hình (Generalization). 

@startuml
skinparam style strictuml
skinparam classAttributeIconSize 0

class User {
  - id : Long
  - username : String
  - fullName : String
  - email : String
  - role : RoleEnum
}

class Student {
  - studentCode : String
  - faceEmbedding : String
  - faceConfidence : Double
  + getVectorArray() : float[]
  + assignClass() : void
}

class Course {
  - id : Long
  - code : String
  - title : String
  - credits : Integer
  - price : BigDecimal
  - status : CourseStatus
}

class Chapter {
  - id : Long
  - title : String
  - orderIndex : Integer
}

class Lesson {
  - id : Long
  - title : String
  - videoUrl : String
  - duration : Integer
}

class Order {
  - id : Long
  - orderCode : Long
  - amount : BigDecimal
  - status : OrderStatus
  + markAsPaid() : void
}

class VietQRPayment {
  - qrCodeUrl : String
  - paymentLinkId : String
  + verifyChecksum() : boolean
}

class FreeEnrollment {
  - enrolledAt : Date
  - isApproved : boolean
  + activateAccess() : void
}

User "1" <-- "1" Student
Course "1" *-- "1..*" Chapter
Chapter "1" *-- "1..*" Lesson
Course "1" <-- "0..*" Order
Student "1" <-- "0..*" Order

Order <|-- VietQRPayment
Order <|-- FreeEnrollment
@enduml

Hình 3.6. Biểu đồ thực thể liên kết (E-R Diagram)

Cấu trúc toàn diện các bảng dữ liệu trong hệ quản trị MySQL 8.0 kèm khóa chính PK và khóa ngoại FK.
erDiagram USERS ||--o| STUDENTS : has_profile FACULTIES ||--o{ STUDENTS : contains CLASSES ||--o{ STUDENTS : contains USERS ||--o{ COURSES : teaches COURSES ||--|{ CHAPTERS : contains CHAPTERS ||--|{ LESSONS : includes STUDENTS ||--o{ ATTENDANCES : attends LESSONS ||--o{ ATTENDANCES : logs USERS ||--o{ ORDERS : places COURSES ||--o{ ORDERS : includes USERS { bigint id PK string username string password string full_name string email string role boolean is_active boolean is_face_registered } STUDENTS { bigint id PK bigint user_id FK string student_code bigint class_id FK bigint faculty_id FK string face_embedding float face_confidence } COURSES { bigint id PK string code string title int credits decimal price string status bigint instructor_id FK } CHAPTERS { bigint id PK bigint course_id FK string title int order_index } LESSONS { bigint id PK bigint chapter_id FK string title string video_url int duration int order_index } ORDERS { bigint id PK bigint order_code bigint user_id FK bigint course_id FK decimal amount string status datetime paid_at } ATTENDANCES { bigint id PK bigint student_id FK bigint lesson_id FK float similarity_score string status datetime checked_at }
💡 Ý nghĩa các quan hệ thực thể:

- USERS ||--o| STUDENTS: Quan hệ 1 - 1 giữa tài khoản và hồ sơ sinh viên kèm dữ liệu sinh trắc học Face AI.
- COURSES ||--|{ CHAPTERS ||--|{ LESSONS: Cấu trúc phân cấp 1 - N của khóa học trực tuyến.
- STUDENTS, LESSONS -> ATTENDANCES: Điểm danh tự động lưu vết sinh trắc học theo từng buổi học.
